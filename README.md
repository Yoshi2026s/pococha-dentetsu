# ポコチャ電鉄・全国編

九州から全国の駅をめぐる、最大4人のすごろくゲームです。GitHub Pagesで配信し、Firebase匿名認証とFirestoreで同期します。

## 遊び方

1. ホストが「部屋を作る」を押し、招待文を共有します。
2. 参加者は同じページで部屋コード4文字を入力します。先着4人です。
3. 全員の準備OK後にホストが開始します。空席にはCPUが入ります。
4. 開始後の新規参加・観戦はできません。

## 切断・再接続

- 人間の操作待ちは部屋の設定に従い（初期値90秒）、時間を超えるとホストがCPU代行します。切断でも席を保持します。同じ匿名UIDの復帰後、次の手番から操作できます。
- ホスト端末が進行担当です。サーバー時刻によるホスト存在確認が設定した切断判定時間（初期値45秒）以上更新されない場合、Firestore側で新しい行動・盤面確定を拒否します。ホスト復帰後に続行できます。担当の自動交代はしません。
- メニューからタイトルへ戻る場合はゲームを中断保存します。ロビーから退出した参加者の席は解放し、ロビーホスト退出では部屋を閉じます。
- ブラウザデータを消す、別ブラウザ・別端末へ移るなどして匿名UIDを失った場合、元の席には戻れません。部屋コードだけで他人の席を引き継ぐ機能はありません。
- 中断・長時間停止中はホスト端末を再度開く必要があります。

## 構成と安全性

Firebaseプロジェクトは `pococha-dentetsu`、既存ウェブアプリは `Pococha`（`1:616265205023:web:1b25848da8be9ca29f5c2a`）を使用します。Firestoreは `(default)`、東京 `asia-northeast1`。Sparkプランを維持し、Firebase Hostingは使用しません。

- `index.html`: 画面、ゲーム計算、同期処理、端末内モード。
- `firebase-config.js`: 公開可能なウェブ接続設定。サービスアカウント鍵は含めません。
- `online.js`: index.htmlへ組み込んでいる通信処理の保守用原本。
- `firestore.rules`: 本番反映用のアクセス制御。GitHubへの保存だけでは反映されません。
- `firebase.json`: ローカル検証用エミュレーター設定。
- `test-online.cjs`: 許可・拒否・競合のエミュレーターテスト。
- `test-dom.cjs`: 端末内モードのDOM動作テスト。レイアウト・タッチ・音声の実機テストは別です。
- `test-audio.cjs` / `test-audio-live.cjs`: BGM・効果音の書き出し検査と実時間の音響検査（Playwrightが必要）。音の仕様は `docs/AUDIO-SPEC.md`。
- `test-wx-bgm.cjs`: 時間帯・天気の小窓（地図全体に重ねない）とBGMの選び方（ふだんはPOP・場面のときだけ場面の曲）のテスト。

部屋のロビー情報（匿名UIDの席割当・準備状態・ホスト・設定）は、コードを知る匿名認証済み利用者が参照できます。部屋一覧の取得は拒否します。盤面・行動履歴・接続情報は参加者限定です。開始後の部屋情報も参加者限定です。表示名を含むロビー情報に個人情報を入れないでください。

参加者は自分の行動要求だけを提出します。ホスト端末がゲーム計算で検算し、盤面と世代番号を同じトランザクションで保存します。席の取得と人数管理、開始とCPU補完も原子的に行います。同じ要求を再送しても一度だけ反映します。ゲームの計算結果・抽選結果をブラウザ演出のためのコールバック内で書き換えません。

この構成は**ホストを信頼する友人間対戦向け**です。ホスト自身の改造・共有seedによる先読み・匿名ユーザーの大量アカウント作成を完全には防げません。賞金・ランキングの公正性をサーバーで保証する構成ではありません。ホストも含めた不正対策には、別途信頼できるサーバー側での状態計算が必要です。

権限情報・手番・世代番号・時刻はネイティブなFirestore型で検証します。入れ子の配列を持つ盤面と行動はJSON文字列で保存しますが、その書き手とサイズをルールで制限し、参加者からの盤面直接更新は拒否します。JSONの内容そのものをルールが検算しているとは扱いません。

## 保存量と料金

画面で購読する手番は直近40件、スタンプは最大4人各1件です。過去の盤面・要求の保存データは今回自動削除しません。長期利用・多数の部屋の作成では保存容量と読み書き量が増えます。無料枠内で遊べる対戦回数は未測定です。上限到達時は通信エラーとして停止し、端末内モードへ勝手に切り替えません。

設定ファイルがないときだけ端末内モードを利用します。設定済みの接続障害・権限エラーとは区別します。

## 検証・公開

```
npm ci
npx firebase emulators:exec --only firestore --project demo-pococha-dentetsu 'node test-online.cjs && node test-dom.cjs'
```

通信のテストは `npm run test:online`（ルールと同期）と `npm run test:online-e2e`（2人分のブラウザで対戦）でも実行できます。実行にはNode.jsとJavaが必要です。エミュレーターはデモ用プロジェクト名を使用し、本番の利用者データでは試験しません。テスト結果は `test-results.json` と `dom-test-results.json` を参照してください。

GitHub Pagesは `main` / `/ (root)` から公開します。秘密鍵・トークンを追加しないでください。ルールの反映はFirebase管理画面または公式CLIで別途行い、公開前に許可・拒否を検証してください。

ロールバックするときは以前のコミットへ戻しますが、旧来の「全匿名ユーザーに全室を許可するルール」へは戻しません。`firestore-before-20261027.rules` は変更前の記録であり、再配備禁止です。

実端末で未確認の操作を、エミュレーター通過だけで成功と報告しません。

## 接続・待ち時間の設定

ロビーの「接続・待ち時間」でホストが開始前に設定します。開始後は変更できません。

- 切断と判断するまで：45秒・1分・1分30秒・2分・3分・5分（初期値45秒）。最後の通信確認から数え、ホストが切断扱いになると進行を停止します。
- 操作待ち・CPU代行まで：1分・1分30秒・2分・3分・5分・10分（初期値1分30秒）。手番開始から数え、接続中でも操作が完了しなければCPUが代行します。
- 既存の部屋は設定値がなければ従来の45秒・90秒を使用します。
